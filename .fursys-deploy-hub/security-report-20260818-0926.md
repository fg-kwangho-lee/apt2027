사내 서버에 올릴 수 있는 상태인지 확인했어요. ✅ 통과 · ❌ 문제 · ➖ 권장입니다.

| 점검 항목 | 결과 | 설명 |
|---|---|---|
| Dockerfile (도커 설정) | ❌ | 배포에 반드시 필요한 Dockerfile이 프로젝트에 없어요. 이게 없으면 사내 서버가 앱을 만들 수 없어 배포를 시작할 수 없습니다. |
| 접속 포트 일치 | ❌ | Dockerfile이 없어 확인할 수 없어요. 정적 웹사이트라면 nginx 기준 80번 포트로 맞추면 됩니다. |
| 시작 방법 | ❌ | Dockerfile이 없어 앱을 어떻게 켜는지 정해져 있지 않아요. nginx 이미지를 쓰면 시작 방법은 자동으로 준비됩니다. |
| 필수 실행 설정값 | ✅ | 화면을 띄우는 데 꼭 필요한 설정값 누락은 없어요. 발견된 설정값 2개는 모두 내 PC와 자동화(깃허브 액션)에서만 쓰는 값이에요. |
| 저장 공간(볼륨) | ✅ | 데이터베이스나 업로드 폴더가 없어 따로 저장 공간을 붙일 필요가 없어요. |

| 앱 구조 | ✅ | 하나로 올리는 단일 앱이에요. 여러 부분으로 나눌 필요가 없습니다. |

### 치명 · 정적 웹사이트용 Dockerfile 만들기
아래 글을 그대로 복사해 AI 도구에 붙여넣으면 이 문제를 고쳐줍니다.
```
이 프로젝트는 빌드 단계가 없는 순수 정적 HTML 사이트(index.html·dashboard.html·itemlist_2026_08/ 등)야. 사내 서버(단일 컨테이너)에 올릴 수 있게 프로젝트 루트에 nginx 기반 Dockerfile 과 .dockerignore 를 만들어줘.

Dockerfile 요구사항:
- FROM nginx:alpine (공식 이미지)
- .html / .json / .txt / .csv / 이미지 / PDF 등 정적 자산을 /usr/share/nginx/html 로 COPY
- EXPOSE 80
- HEALTHCHECK 은 반드시 localhost 가 아니라 127.0.0.1(IPv4 명시)로:
  HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 CMD wget -q --spider http://127.0.0.1/ || exit 1
- nginx custom conf 를 둘 경우 server 블록에 listen 80; 과 listen [::]:80; 을 모두 명시
- 한글 파일명이 많으니 nginx conf 에 charset utf-8; 을 넣어줘

.dockerignore 요구사항:
- .git, node_modules, .env, *.zip, *.xlsx, pdfs/, .claude/, .fursys-deploy-hub/, scripts/, *.js(빌드/수집용 로컬 스크립트), *.mjs, *.py 를 제외해서 로컬 도구 코드가 컨테이너에 들어가지 않게 해줘

주의: docker-compose 나 빌드팩은 쓰지 말고 Dockerfile 단독으로 만들어줘.
```
